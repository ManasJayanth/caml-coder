## Non-negotiable invariants

- Immutable source snapshots, raw model outputs, observations, review decisions and ancestry. No invented executions or transcripts edited into success.
- No silent target/history truncation. Related documents, translated examples, task variants, retries and episode prefixes remain in one split.
- Final holdout is sealed. If its failures inform model, data, export or harness changes, retire it and establish a new independent holdout before claiming held-out improvement.
- Fixture E2Es are not real-model evidence. Missing, skipped, stale, blocked or unrun required checks cannot count as passing.
- All agent tool operations execute in isolated containers. The host SDK may contact local inference only. No host fallback.
- No silent alternative models, weakened acceptance limits, hidden stochastic retries or replacement of real integrations with stubs.
- Python owns CLI/pipeline/MLX; TypeScript provides a thin pinned Pi SDK runner. Only E2E tests; no unit tests or internal mocks.

## Work loop for smaller coding models

Work cards live in `config/cards.json`. Cards have a concrete behavior, prerequisites, scoped files, contract, exclusions, assertions, E2E commands and evidence tier. Administrative bootstrap/configuration files are established up front. Aim for at most four production modules per card; tests and bounded fixtures are additional. Each task family and review batch gets its own bounded child card rather than asking one model to invent the whole catalogue.

1. Run `work next`; read the printed context and exact prerequisite evidence. A card must be dependency-ready. Smaller coding models receive one bounded card at a time, with allowed files, prerequisites, acceptance contract and E2E command already stated.
2. Run its current public-command E2E to establish behavior. Implement only the scoped changes.
3. Run the card's positive and negative E2Es and affected downstream E2Es. Inspect artifacts and assertions, not just exit codes.
4. `work record` binds a pass to current evidence. Checkpoint changes and retain failures. Changes invalidate evidence and approvals downstream; conservative whole-implementation invalidation is acceptable initially.
5. At most three failed repair iterations. Then mark NEEDS_REPLAN and print evidence, diff and a small escalation request. Do not widen architecture or weaken requirements autonomously.
6. Advance, block on a concrete prerequisite, or enter WAITING_APPROVAL. Ordinary status records cannot clear WAITING_APPROVAL or NEEDS_REPLAN. The separate APPROVALS card runs immediately after T04 (depending on R1, R2, T03 and T04), so an early repair hold cannot create a dependency cycle through T23. It must define and prove an artifact-bound trusted user authorization mechanism before a hold can be resolved; a worker-authored JSON receipt is not authorization.

Statuses: PENDING, RUNNING, PASSED, FAILED, BLOCKED, WAITING_APPROVAL; NEEDS_REPLAN is the explicit escalation state. STALE is a computed evidence state, never a pass. Classify implementation, infrastructure, quality, approval, replan and interruption failures separately. Task completion is not proof of test execution.

Versioned records describe sources/chunks, attempts, executable tasks, episodes, reviews, training rows, manifests, E2E evidence and work cards. Attempts bind input/generator/config/seed/status/raw continuation/finish reason/failure classification. Canonical UTF-8 JSON (sorted keys, no NaN or duplicate keys) defines content hashes. Atomic writes use same-filesystem staging and a no-overwrite commit. Keep run-specific directories. SQLite triggers reject accidental UPDATE/DELETE statements against workflow and attempt event tables. They are a local rewrite guard, not a security boundary against a host database owner who can replace the database or drop triggers; integrity claims rely on the recorded evidence digests and trusted process boundaries, not cryptographic event security. The transactional attempts ledger allows recomputation after a crash but exactly one canonical committed result per attempt. Immutable histories retain superseded evidence; never overwrite failures to look successful.

## E2E layers and completion criteria

All tests launch the CLI or Pi runner as subprocesses and inspect externally observable files, requests, tool results and grades. No internal function, filesystem, grading or persistence mocks.

- Deterministic E2E: real pipeline persistence, real Pi and real containers when those stages exist. A scripted local inference HTTP server is allowed as an external response/fault fixture.
- Real-model E2E: pinned Bonito, Qwen and teacher weights, actual MLX/Ollama and actual toolchains.
- Acceptance E2E: pilot yields, approvals, final dataset, training and paired benchmark gates.

Test timeouts, malformed JSON/JSONL, duplicate IDs, unknown fields/schema versions, hash conflicts, crash windows, concurrent attempts, stale reviews, empty buckets, leakage, unsafe paths/symlinks, network access, hidden-test tampering, fake success output, overlong contexts, truncation, invalid tool calls, repeated calls, missing associations, provider failures and boundary off-by-one behavior. Every critical path needs real evidence before final success. No skip-to-green.

## Bonito

Acquire exact model commit and file hashes. Upstream weights are `.bin`; convert shardwise using safe `weights_only` loading to safetensors, preserving tensors, BF16 and tokenizer assets, then convert to MLX BF16. Verify dtype, tensor mapping and token IDs. No unsafe arbitrary pickle fallback.

Do not apply a chat template. Exact input:

```
<|tasktype|>
{full task name}
<|context|>
{stripped passage}
<|task|>
```

Task names: `question answering without choices`, `extractive question answering`, `summarization`. Parse only the generated continuation: exactly one `<|pipe|>`, nonempty instruction and answer; substitute literal `{{context}}` in both halves. Ordinary code braces are legal. Record token IDs, EOS and stop reason; max-length termination is a rejection.

Limits: source ≤1536 Bonito tokens; full prompt ≤2048; generation ≤1024; total ≤4096; student-rendered docs ≤4096. Temperature 0.5, top_p 0.95, no extra penalties, fixed recorded sequential seeds. Bonito's Mistral sliding window is 4096; MLX's mapping to full-attention llama cannot justify longer-context equivalence. Teacher-forced fixed-fixture parity requires identical input IDs and BF16 atol 0.1, rtol 0.02. Investigate mismatch; never relax tolerances just to pass.
