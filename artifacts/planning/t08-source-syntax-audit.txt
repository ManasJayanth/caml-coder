T08 pinned-source syntax audit (read-only)

Scope: `artifacts/sources/official-stable-sources-002`, the pinned 170-file snapshot used by `config/eligibility.json` (166 Markdown docs plus non-document files). Plan contract: `docs/PLAN.md:56` requires preserving frontmatter, heading ancestry, language labels, whole fences, tabs/admonitions and included prerequisites; detect unresolved includes/cycles and quarantine malformed text.

Concrete source patterns and extraction implications

- YAML frontmatter is common and not uniform. `ocaml/data/tutorials/guides/0tt_04_calling_fortran_libraries.md:1-8` has a folded `description: >` and quoted category; `ocaml/data/tutorials/platform/0_00_bootstrap_project.md:1-8` has quoted values and `description: |`; `melange/docs/index.md:1-27` has VitePress home-page metadata and embedded HTML in a feature description. Parse a delimited YAML block, retain its fields as metadata, and do not leak YAML into prose or mistake `---` for a section rule.
- Headings use ATX form at multiple levels, often nested deeply; e.g. `melange/docs/advanced-js-interop.md:1-20` walks H1 through H4 and later H5 (`:190`). Derive ancestry with a stack and ignore heading-looking lines inside fences. Frontmatter delimiters and `---` separators can otherwise look like headings/rules.
- There is no `<Tabs>`/`<TabItem>` component markup in this corpus. The real language-tab equivalent is consecutive language-labelled code fences: `melange/docs/advanced-js-interop.md:23-36` alternates `ocaml` and `reasonml`, and `melange/docs/build-system.md:127-...` uses adjacent `ocaml`/`reasonml` examples. Preserve each complete fence and its language label, and keep the paired examples associated instead of merging or deduplicating them.
- Admonitions are raw HTML, not only Markdown `!!!`/`:::` syntax. OCaml tutorial notes use `<div class="note">` around a heading and paragraphs (`ocaml/data/tutorials/language/5rt_01_garbage-collector.md:80-100`). Melange uses `<div class="text-reasonml">` and `text-ocaml` wrappers around prose/code (`melange/docs/build-system.md:78-86,114-120`). Keep the inner text and wrapper semantics as a block/metadata; naive HTML stripping loses the warning and which syntax variant the instruction targets.
- Melange embeds executable example prerequisites in comments of the form `<!--#prelude# ... -->`, immediately before the example they support: `melange/docs/advanced-js-interop.md:120-133` and an inline form at `:264`. Treat these as example setup/context and associate them with the following fence; generic HTML-comment deletion would make examples incomplete. OCaml tutorials also use `<!-- $MDX skip -->` immediately before code (`ocaml/data/tutorials/guides/0tt_04_calling_fortran_libraries.md:135`; similarly `1wf_01_debugging.md:283-294`); keep or interpret this directive without dropping the example.
- No actual include directive (`include::`, Liquid/Jinja include, or HTML include marker) was found in the pinned Markdown documents. Ordinary prose containing “include” and C preprocessor lines such as `#include <stdio.h>` (`ocaml/data/tutorials/language/5rt_03_compiler_backend.md:480-484`) are not document includes. Keep local Markdown links as links; do not recursively inline arbitrary links. If include syntax is added later, resolve only an explicit allowlisted directive relative to the pinned snapshot, with cycle/missing-target quarantine per the plan.
- Markdown also contains reference definitions and footnotes that affect complete context: `esy/docs/configuration.md:343,380` defines link references and `melange/docs/syntaxes.md:219-222` defines footnotes. Preserve definitions/associations during normalization rather than treating them as unrelated prose.
- Fences include many languages and indented fences, e.g. `esy/docs/multiple-sandboxes.md:48-62` (nested/indented `shell`) and multiple code languages throughout Melange. A line-oriented regex must track opening fence character, run length and indentation, and retain the entire block plus info string. OCaml code comments and shell examples contain `#` lines; these are not Markdown headings.
- The pinned document set is Markdown (`.md`); no `.mdx` or `.rst` source files were present. MDX-like directives appear as HTML comments, not standalone MDX files. A parser should explicitly support observed constructs and quarantine unsupported embedded syntax rather than silently strip it.

Summary recommendation: normalize structure with a stateful Markdown scanner (frontmatter, fenced blocks, heading stack, HTML blocks/comments, reference definitions), then emit chunks that carry path, heading ancestry, language labels, admonition kind and source span. Keep paired OCaml/Reason examples and `#prelude#` context linked. No source files or tests were changed/run for this audit.
