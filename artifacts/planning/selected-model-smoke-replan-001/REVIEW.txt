Current defects found in review

- `_container_script` still prints the same randomized completion marker after `./probe` returns. The checker also prints that marker only after assertions, but the shell copy makes the completion check unsound: a candidate can execute `exit 0` during module initialization, skip the checker, then let the shell print the marker and exit successfully. A specific negative fixture is `let sum_squares _ = 0\nlet () = exit 0`.
- Container names append a random suffix and then truncate the complete string to 63 characters. A sufficiently long valid `--run-id` consumes the suffix, allowing concurrent invocations to collide. Bound or validate the run ID length so the random suffix remains intact, or truncate the run-ID portion before appending the suffix.
- The latest `ulimit -f 128` adjustment is unverified. The reference fixture has not passed, and no negative fixture has run.

Proposed bounded patch and evidence

1. Remove the shell's marker `printf`; retain the marker only in `checker.ml` after all fixed assertions. Continue requiring the exact marker as the last stdout line and a zero container exit code.
2. Reserve room for the random container-name suffix by limiting the run-ID portion before composing the name, or reject overly long run IDs while preserving the suffix.
3. After the checker is frozen, run one synthetic reference candidate and the early-exit negative candidate in the pinned isolated container. The reference must pass; the negative must fail because the checker-only marker is absent. Record both immutable reports. Do not run the actual model artifact as part of this synthetic review.

This checker is a compile-and-fixed-example smoke test only. It is not benchmark evidence, robustness evidence, or model acceptance.
